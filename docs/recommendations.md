# ข้อเสนอเพิ่มเติม — ยังไม่ได้เพิ่มในระบบ

แยกจากงาน backend ที่จำเป็นใน backend-contract.md รายการต่อไปนี้ต้องตัดสินใจก่อนขยายขอบเขต

| ลำดับ | ควรเพิ่ม | ปัญหาที่ป้องกัน |
|---|---|---|
| 1 | subjects / enrollments / Section แยกวิชาและภาคเรียน | คนหนึ่งอาจอยู่ต่าง Section ในแต่ละวิชา; Dashboard อาจแสดงงานที่ไม่ได้เรียน |
| 2 | ประวัติแก้ไข + เหตุผลปฏิเสธ + ผู้ดำเนินการ | ปัจจุบันมีแค่สถานะล่าสุดและ reviewer ย้อนเหตุการณ์หรือเหตุผลไม่ได้ |
| 3 | version จากตอนเปิดฟอร์ม + หน้าจอแก้ conflict | ผู้ดูแลสองคนอาจเขียนทับกัน ปิดปุ่มฝั่งเดียวไม่ช่วยข้ามเครื่อง |
| 4 | ถังขยะ/ระยะเวลากู้คืนและ backup | ลบงานแล้ว progress ถูกลบตาม ความผิดพลาดกระทบหลายคน |
| 5 | ตรวจลิงก์เสีย/สิทธิ์เอกสาร + submission_url แยกจากชื่อช่องทาง | URL ถูกต้องไม่ได้แปลว่าเปิดได้ และชื่อ Teams ไม่ใช่ลิงก์ห้องส่งงาน |

ระบบเลือกจำกัดสมาชิกด้วยรหัสนิสิตขึ้นต้น `6802` ที่ frontend, profile trigger, constraint และ restrictive RLS แทนการจัดการ allowlist แยก ก่อนเปิดใช้จริงควรตกลงเจ้าของข้อมูล ระยะเวลาเก็บบันทึกส่วนตัว การลบข้อมูลเมื่อจบรุ่น และผู้ดูแลสำรอง

ยังไม่เพิ่ม push/email, chat, คะแนน, file upload หรือ analytics เพราะไม่ใช่ขอบเขตที่ขอในรอบนี้
